# 隐私与数据

Agent 会话记录里常有源代码、文件内容、命令输出，以及你在提示词里输入的任何内容，有时还包括密钥。Origin 会复制这些记录，让它们不受 Agent 自身清理的影响。本页说明 Origin 保存了什么，以及如何清除。

## Origin 保存了什么 {#what-origin-stores}

所有数据都在同一个目录 `~/.origin`（或 `ORIGIN_HOME`）中：

- `origin.db`：SQLite 数据库，包含规范化后的事件、检索索引、你的条目，以及所有遗忘与恢复的记录。
- `raw/`：原始会话记录文件的只追加副本，以 zstd 压缩：每个副本是一个由压缩帧组成的 `.zst` 文件，加上一个存放最新若干行的 `.tail` 文件。中枢也可以把压缩帧改存到存储桶中（见[把原始镜像放进存储桶](./hub.md#keep-raw-mirrors-in-a-bucket)）。

你的数据只存放在你控制的机器上：你的设备，以及你自建的中枢（如果有）和你为它配置的存储桶（如果有）。Origin 从不调用第三方服务，也不调用任何 LLM API。没有中枢时，它不发起任何网络连接；使用中枢时，唯一的网络流量发生在你的设备和你的中枢之间，以及中枢和它的存储桶之间。该目录没有加密，请像保护原始记录一样保护它。

## 遗忘 {#forgetting}

`origin forget <id> --reason <text>`（或 Agent 的 `forget` 工具，仅在你要求时使用）会隐藏一个条目或事件，以及依赖它的内容：

1. **遗忘一个条目**：隐藏它的所有版本，以及它引用的事件。
2. **遗忘一个事件**：隐藏该事件，以及所有引用它的条目。
3. **来源全部被隐藏的条目**也会一并隐藏。

被隐藏的条目和事件会从检索、时间线和所有 MCP 工具中消失，也不能被引用，重新同步也不会回来。例如，你可以对粘贴过密钥的那条提示词运行 `origin forget <event-id> --reason "pasted a secret"`。

每一次遗忘都会保存为一条记录，包括原因、时间、地点和操作者：Agent 可以替你遗忘，但必须说明原因。`origin forgotten` 会列出这些记录，[管理界面](./admin.md)的遗忘记录页面也会。

**恢复。** 你可以随时恢复一次遗忘来撤销它，并给出原因：运行 `origin restore <tombstone-id> --reason <text>`，或者在管理界面中这次遗忘的页面上点击**恢复**，那个页面也会向你展示它隐藏的内容。它隐藏的内容会回来，仍被其他遗忘隐藏的除外。恢复本身也是一条记录，所以历史始终完整；要再次隐藏，就再遗忘一次。只有你能恢复：Agent 没有用于恢复的工具。

遗忘是**隐藏**，而不是擦除：由于归档只追加，`~/.origin/raw/` 下的镜像文件仍保留原始行，恢复也依赖它们。要彻底删除数据，见[清除全部数据](#removing-everything)。

## 使用个人中枢时 {#with-a-personal-hub}

[个人中枢](./hub.md)会改变数据的存放位置：

- **你控制的服务器**：中枢保存所有已接入设备的会话以及你全部条目的完整副本。只在你自己控制的机器上运行它，并像保护 `~/.origin` 一样保护它的数据目录。
- **TLS 与令牌**：中枢使用明文 HTTP，开放之前请放在 TLS 之后。除 `/healthz` 外，每个请求都需要令牌。中枢只保存令牌的哈希；设备丢失或退役时，可以吊销对应的令牌。设备的令牌只对这台设备有效，所以无法冒充另一台设备写入。
- **遗忘与恢复会同步到每台设备**：无论在设备上还是在中枢上遗忘或恢复，中枢和随后的每台设备都会在下一次同步时应用同一条记录。即使某台设备再次推送，被遗忘的事件也保持隐藏。
- **每台设备保存什么**：每台设备保存自己的会话和条目，并把它们发送到中枢；它从不接收其他设备的会话或条目。遗忘在每个库中都会隐藏数据；但和其他地方一样，原始镜像文件里仍保留原始行。
- **存储桶里保存着你的会话**：如果中枢把原始镜像保存在存储桶中，存储桶里就有原始行——经过压缩但没有加密——也包括已遗忘事件的原始行。请使用你自己运行的对象存储，例如 MinIO，或者像信任中枢本身一样信任的存储；给中枢的密钥只应能访问它自己的前缀，并且在中枢所在的网络之外通过 https 访问存储桶。
- **管理界面会显示你的会话**：如果启用了中枢的[管理界面](./admin.md)，任何知道管理密码的人都能在浏览器里阅读你归档的会话和条目。请像保护中枢本身一样保护这个密码。被遗忘的条目和事件的文本，只出现在隐藏它们的那次遗忘的页面上，供你决定是否恢复。
- **审计日志会记录客户端**：登录和管理操作会连同客户端地址和浏览器的 user agent 记录在中枢上，但从不记录条目或事件的文本。
- **CDN 能看到解密后的流量**：终止 TLS 的 CDN 或代理能看到经过它的一切：设备推送的内容、Agent 读取的内容，以及管理界面展示给你的内容。如果你在意这一点，请优先通过[私有访问](./admin.md#private-access)使用管理界面。

## 备份 {#backing-up}

`origin backup <dir>` 把一个库备份到一个目录中，即使 Agent 或中枢正在使用它：

```bash
origin backup /backups/origin
```

它先用 SQLite 的在线备份一次性复制 `origin.db`，所以副本是一个一致的快照，然后按这个副本记录的状态复制 `raw/` 镜像。压缩帧永远不变，所以再次备份到同一个目录时只复制新的帧和最新的若干行。恢复时，把这个目录复制到一个空的 `ORIGIN_HOME` 中（在中枢上是 `/data` 卷）。与库本身一样，备份中仍保留已遗忘事件的原始行。

如果中枢把原始镜像保存在[存储桶](./hub.md#keep-raw-mirrors-in-a-bucket)中，请在配置了存储桶的中枢上运行 `origin backup`。它把存储桶中的压缩帧复制到备份目录里，布局与没有存储桶时相同，所以备份包含一切，恢复方式也完全一样，有没有存储桶都可以；恢复后的库把帧保存在磁盘上，直到再次为它配置存储桶。第一次备份会下载所有帧，之后只下载新的帧。存储桶中的对象永远不会被修改或删除，所以你也可以单独备份存储桶，但备份目录从不需要它。

复制一个正在使用的大数据库的其他方法要么更慢，要么不安全。`VACUUM INTO` 会重建每一张表和每一个索引，要花很多倍的时间（20 GB 的数据库约需 13 分钟，而不是 40 秒）。`sqlite3` 的 `.backup` 命令分小步复制，一旦有其他进程写入就从头开始，而 Agent 运行时 Origin 每隔几秒就会写入。直接复制文件只有在没有 Origin 进程运行时才是一致的，因为最近的写入可能还在 `origin.db-wal` 中。

## 清除全部数据 {#removing-everything}

删除 `~/.origin`（或你设置的 `ORIGIN_HOME`）。没有中枢时，Origin 不在其他任何地方保存数据；使用中枢时，还要删除中枢的数据目录（容器内为 `/data`），如果它有存储桶，还要删除其前缀下的对象，并吊销该设备的令牌。同时从各 Agent 中移除 MCP 注册（Claude Code：`claude mcp remove --scope user origin`）。

## 报告问题 {#reporting-a-problem}

如果你发现 Origin 可能泄露、暴露或损坏你的数据，请按[安全策略](https://github.com/openlinkos/origin/blob/master/SECURITY.md)私下报告。
