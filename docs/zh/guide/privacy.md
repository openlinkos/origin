# 隐私与数据

Agent 会话记录里常有源代码、文件内容、命令输出，以及你在提示词里输入的任何内容，有时还包括密钥。Origin 会复制这些记录，让它们不受 Agent 自身清理的影响。本页说明 Origin 保存了什么，以及如何清除。

## Origin 保存了什么 {#what-origin-stores}

所有数据都在同一个目录 `~/.origin`（或 `ORIGIN_HOME`）中：

- `origin.db`：SQLite 数据库，包含规范化后的事件、检索索引、你的条目，以及所有遗忘记录。
- `raw/`：原始会话记录文件的只追加副本。

你的数据只存放在你控制的机器上：你的设备，以及你自建的中枢（如果有）。Origin 从不调用第三方服务，也不调用任何 LLM API。没有中枢时，它不发起任何网络连接；使用中枢时，唯一的网络流量发生在你的设备和你的中枢之间。该目录没有加密，请像保护原始记录一样保护它。

## 遗忘 {#forgetting}

`origin forget <id>`（或 Agent 的 `forget` 工具，仅在你要求时使用）是永久的：

1. **遗忘一个条目**：遗忘它的所有版本，并隐藏它引用的事件。
2. **遗忘一个事件**：隐藏该事件，并遗忘所有引用它的条目。
3. **来源全部被隐藏的条目**也会一并遗忘。

被遗忘的条目和事件会从检索、时间线和所有 MCP 工具中消失，也不能再被引用，重新同步也不会回来。例如，你可以对粘贴过密钥的那条提示词运行 `origin forget <event-id>`。

遗忘是**隐藏**，而不是擦除：由于归档只追加，`~/.origin/raw/` 下的镜像文件仍保留原始行。

## 使用个人中枢时 {#with-a-personal-hub}

[个人中枢](./hub.md)会改变数据的存放位置：

- **你控制的服务器**：中枢保存所有已接入设备的会话以及你全部条目的完整副本。只在你自己控制的机器上运行它，并像保护 `~/.origin` 一样保护它的数据目录。
- **TLS 与令牌**：中枢使用明文 HTTP，开放之前请放在 TLS 之后。除 `/healthz` 外，每个请求都需要令牌。中枢只保存令牌的哈希；设备丢失或退役时，可以吊销对应的令牌。设备的令牌只对这台设备有效，所以无法冒充另一台设备写入。
- **遗忘会同步到每台设备**：无论在设备上还是在中枢上遗忘，中枢和随后的每台设备都会在下一次同步时应用同一条遗忘记录。即使某台设备再次推送，被遗忘的事件也保持隐藏。
- **每台设备保存什么**：每台设备保存自己的会话和条目，并把它们发送到中枢；它从不接收其他设备的会话或条目。遗忘在每个库中都会隐藏数据；但和其他地方一样，原始镜像文件里仍保留原始行。
- **管理界面会显示你的会话**：如果启用了中枢的[管理界面](./admin.md)，任何知道管理密码的人都能在浏览器里阅读你归档的会话和条目。请像保护中枢本身一样保护这个密码。界面从不显示被遗忘的条目或事件的文本。
- **审计日志会记录客户端**：登录和管理操作会连同客户端地址和浏览器的 user agent 记录在中枢上，但从不记录条目或事件的文本。
- **CDN 能看到解密后的流量**：终止 TLS 的 CDN 或代理能看到经过它的一切：设备推送的内容、Agent 读取的内容，以及管理界面展示给你的内容。如果你在意这一点，请优先通过[私有访问](./admin.md#private-access)使用管理界面。

## 备份 {#backing-up}

`origin backup <dir>` 把一个库备份到一个目录中，即使 Agent 或中枢正在使用它：

```bash
origin backup /backups/origin
```

它先用 SQLite 的在线备份一次性复制 `origin.db`，所以副本是一个一致的快照，然后再复制 `raw/` 镜像。镜像只会增长，所以再次备份到同一个目录时只复制新增的部分。恢复时，把这个目录复制到一个空的 `ORIGIN_HOME` 中（在中枢上是 `/data` 卷）。与库本身一样，备份中仍保留已遗忘事件的原始行。它需要 Node.js 22.16 或更高版本。

复制一个正在使用的大数据库的其他方法要么更慢，要么不安全。`VACUUM INTO` 会重建每一张表和每一个索引，要花很多倍的时间（20 GB 的数据库约需 13 分钟，而不是 40 秒）。`sqlite3` 的 `.backup` 命令分小步复制，一旦有其他进程写入就从头开始，而 Agent 运行时 Origin 每隔几秒就会写入。直接复制文件只有在没有 Origin 进程运行时才是一致的，因为最近的写入可能还在 `origin.db-wal` 中。

## 清除全部数据 {#removing-everything}

删除 `~/.origin`（或你设置的 `ORIGIN_HOME`）。没有中枢时，Origin 不在其他任何地方保存数据；使用中枢时，还要删除中枢的数据目录（容器内为 `/data`），并吊销该设备的令牌。同时从各 Agent 中移除 MCP 注册（Claude Code：`claude mcp remove --scope user origin`）。

## 报告问题 {#reporting-a-problem}

如果你发现 Origin 可能泄露、暴露或损坏你的数据，请按[安全策略](https://github.com/openlinkos/origin/blob/master/SECURITY.md)私下报告。
